## 一、结论

服务器1 上 **500→2000** 四段 adapter 接续曾跑通（PEFT 加载、`lora_B` 全非零、fa2 日志正常），但 **不构成** Stage 1 效果复现；**堆 step 对 temporal 几乎无效**（40 条 balanced 全程 **6/40**）。排期可按 **~40 min/500 step**；全段纯训练约 **3.3 h**（不含探针）。后续训练见 `t3-autodl2…/25`，勿再续本路线 LoRA。

## 二、训练速度与资源

**配置**：`save_only_model` 分段；`--adapter_name_or_path` 接续；日志须见 `Using FlashAttention-2`、`Applied SFT learning rate … to … time-series encoder`。


| 指标        | 四段共性（500→2000）                       |
| --------- | ------------------------------------ |
| 秒/step    | ~4.8–5.0                             |
| steps/s   | ~0.20–0.21                           |
| samples/s | ~1.64–1.67                           |
| 排期粗算      | **8 step/min**；500 step ≈ **40 min** |


规律：墙钟与 **train_loss 高低无关**（初段 loss 3.86 与末段 0.41 同速）；瓶颈在固定 batch 与数据管线，不在 backward 复杂度变化。

**显存**：探针生成峰值约 **8.5–8.8GB**（30/40 条），远低于 A100 40GB；与 full FT + offload 在 CPU cgroup 顶满（报告 15）形成对比。

**产物大小**：`save_only_model` 段约 **159M**；2000 段含 optimizer state 约 **287M**（正常，非膨胀）。

## 三、探针与任务规律

探针为 **训练集**小样本，**不能**当 ST-Test 或论文效果。须固定 **30 条健康** + **40 条 temporal balanced** 面板；6 条探针过窄会高估（如 4/6）。

**任务饱和顺序**：spatial yes/no 最先满（10/10）；spatial_temporal 枚举次之；**temporal 连续数值最慢**。

**边际收益**：500→1000 时 30 条 +4/30；1000→1500 +2/30、temporal +1/10；1500→2000 30 条仅 +1、temporal **不变**。**停训看探针面板，不看 loss 斜率。**

**temporal 分项**（40 条，每题型 5 条，1500/2000 均为 6/40）：evolution_pattern **4/5**，kappa **2/5**；amplitude / frequency / phase / baseline / sigma / lambda **0/5**。

**失败模式**：常输出错误 **常数**（amplitude `20.0`、frequency `0.0364`、phase `-1.5708`），更像答案先验而非读序列；非随机错。

**alignment 规模**（约 15.37 万条总量）：temporal 子集约 **63,943**；sinusoidal 三类各约 **12,943**；evolution/baseline 各约 **6,227**；kappa **6,216**；sigma **4,616**；lambda **1,827**。短 LoRA 相对全量 **严重欠训**。

## 四、接续与 resume 口径

### 4.1 adapter 接续（500→1500）

- `save_only_model=True` → checkpoint **无** `optimizer.pt` / `scheduler.pt` / `rng_state.pth`。
- 用 `--adapter_name_or_path` 指向上一段 `output_dir`，**新** `output_dir` 开 run，`max_steps=500` 每段。
- LLaMA-Factory：`PeftModel.from_pretrained(..., is_trainable=True)` 加载末段 adapter。
- **只继承权重**，每段新 Trainer / optimizer / scheduler；**不宜**称「等价连续 N step」。

### 4.2 2000 save_state 段

从 1500 adapter 开新 run，但 **保存完整 Trainer state**（`checkpoint-500` 含四类 state 文件），曾可作 `resume_from_checkpoint` 入口；与 500→1500 纯 adapter 接续不同。续到 2500 **已取消**。

### 4.3 strict resume 避坑（脚本已删，逻辑仍可用）

- **SOURCE_DIR** 只读断点；**OUTPUT_DIR** 名称反映 **目标步数**（如 `2500steps_from2000`），勿与 SOURCE 同名。
- 写回同源目录 + `save_total_limit=1` 可能 **轮转掉** 可 resume 断点。
- strict resume 前置缺一不可：`optimizer.pt`、`scheduler.pt`、`rng_state.pth`、`trainer_state.json`。仅 `adapter_model.bin` → 只能 adapter 接续。
- 2000 时 temporal 6/40；再续 500 step 仍约 40 min、探针收益极低；取消主因是 **效果天花板** 而非脚本 bug。
