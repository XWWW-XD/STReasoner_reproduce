# 服务器2单卡 A800 80G 的 4B 三阶段训练方案

## 1. 总结结论

这份方案不沿用 `15-单卡A100训练复现可行性研究.md` 的保守结论。

### 旧策略

前提是：

```text
单卡 A100-PCIE-40GB
容器 CPU memory.max 约 77.3GB
数据盘约 50G
4B full fine-tuning + ZeRO-3 CPU offload 在 optimizer states 初始化时被 -9 杀掉
```

现在服务器 2 的资源假设是：

```text
单卡 A800 80G
数据盘 100G
```

### 新策略

```text
优先尝试 4B full fine-tuning。
优先使用 GPU-only，不先上 LoRA / QLoRA / 只训 TS encoder。
Stage 1 / Stage 2 先复现全参 SFT。
Stage 3 仍走 S-GRPO，但单卡缩 rollout 和 batch。
只有 full 路线在 A800 80G 明确失败后，才退到 optimizer offload 或 LoRA。
```

## 2. 当前不应继续照搬的保守点

上一份报告里这些建议不再作为服务器 2 的默认路线：

- 不默认 LoRA / QLoRA。
- 不默认只训 `ts_encoder`。
- 不默认 ZeRO-3 CPU offload。
- 不默认 `cutoff_len=4096` 作为最终训练长度。
- 不默认 micro batch 只能为 1。

服务器 2 的默认路线应更接近官方 4B 脚本：

```text
scripts/qwen3-4b-instruct/train_stage1.sh
scripts/qwen3-4b-instruct/train_stage1+2.sh
scripts/qwen3-4b-instruct/train_stage1+2+3_w_spatial.sh
```

但要把多卡参数改成单卡参数，并加入服务器 2 的 cache、日志和 checkpoint 控制。

## 3. 训练资源判断

4B TS 模型当前约：

```text
参数量：约 4.44B
fp16/bf16 权重目录：约 8.3G
```

full SFT 的显存压力主要来自：

- 模型权重。
- 梯度。
- Adam optimizer states。
- fp32 master weights 或等价优化器状态。
- activation，受 `cutoff_len`、micro batch、gradient checkpointing、FlashAttention 影响最大。

在 A800 80G 上，4B full SFT 值得优先尝试。比较合理的预期是：

```text
cutoff_len=8192 + micro batch=1：应作为第一档 GPU-only full smoke。
cutoff_len=8192 + micro batch=2：应作为第二档上探。
cutoff_len=10000 + micro batch=1/2：在 8192 稳定后再试，接近官方脚本。
```

如果 GPU-only 在 optimizer 或 backward 阶段 OOM，先不要直接跳 LoRA，fallback 顺序应是：

```text
1. 降 micro batch 或 cutoff_len。
2. 保持 full，改 ZeRO-3 optimizer/param offload。
3. 仍失败，再考虑 LoRA / QLoRA / 只训 TS encoder。
```

## 4. Stage 0：服务器 2 门禁检查

每次正式训练前先做门禁，不直接从训练脚本开跑。

```bash
cd /root/autodl-tmp/STReasoner_reproduce

nvidia-smi
df -h / /root/autodl-tmp
du -sh base_model/Qwen3-4B-Instruct-2507 data/ST-Bench output cache 2>/dev/null || true
cat /sys/fs/cgroup/memory.max 2>/dev/null || true
free -h

/root/autodl-tmp/conda/envs/str-py310/bin/python \
  00_new_codes/repro_autodl/experiments/scripts/single_a100_qwen3_4b_model_check.py

bash 00_new_codes/repro_autodl/experiments/scripts/single_a100_qwen3_4b_env_check.sh
```

门禁通过标准：

- `nvidia-smi` 显示单张 A800 80G 空闲。
- `/root/autodl-tmp` 至少剩 35G，最好剩 45G 以上。
- `/` 不放模型和 checkpoint，系统盘占用最好低于 50%。
- 4B 模型、ST-Bench 数据完整。
- 没有残留训练、vLLM、EasyR1 进程。

数据盘虽然是 100G，但 full checkpoint 和 RL checkpoint 会很快占空间，所以仍要限制 checkpoint 数量。这是磁盘管理，不是训练保守化。

## 5. Stage 1：全参 Alignment SFT

### 5.1 首选路线

首选：

```text
full fine-tuning
bf16
flash_attn fa2
DeepSpeed GPU-only ZeRO-3
不使用 CPU offload
不使用 LoRA
```

对应 DeepSpeed 配置优先使用：

```text
ds_config/zero3.json
```

不要继续默认用：

```text
ds_config/ds_config_3_offload_all.json
```

上一台机器死在 CPU offload 的 optimizer states 初始化阶段。服务器 2 有 80G 显存，第一轮应该让 optimizer 尽量在 GPU 跑，避免又把瓶颈转移到 CPU cgroup。

### 5.2 Stage 1 smoke，不是省内存版

先做 20-step smoke，但参数不要缩到过低：

```bash
cd /root/autodl-tmp/STReasoner_reproduce

export PATH="/root/autodl-tmp/conda/envs/str-py310/bin:${PATH}"
export PYTHONPATH=.
export HF_HOME=/root/autodl-tmp/cache/huggingface
export HF_HUB_CACHE=/root/autodl-tmp/cache/huggingface
export TRANSFORMERS_CACHE=/root/autodl-tmp/cache/huggingface
export HF_DATASETS_CACHE=/root/autodl-tmp/cache/huggingface/datasets
export TORCH_HOME=/root/autodl-tmp/cache/huggingface/torch
export TRITON_CACHE_DIR=/root/autodl-tmp/cache/triton
export TORCH_EXTENSIONS_DIR=/root/autodl-tmp/cache/torch_extensions
export WANDB_DISABLED=true

NCCL_DEBUG=WARN DEEPSPEED_TIMEOUT=1800 \
/root/autodl-tmp/conda/envs/str-py310/bin/deepspeed --num_gpus 1 --master_port=19921 src/train.py \
  --deepspeed ds_config/zero3.json \
  --stage sft \
  --model_name_or_path "./base_model/Qwen3-4B-Instruct-2507" \
  --flash_attn fa2 \
  --dataset "alignment" \
  --interleave_probs "1" \
  --do_train \
  --mix_strategy "interleave_over" \
  --template "STReasoner-Align" \
  --finetuning_type full \
  --output_dir "./output/a800_qwen3_4b_stage1_full_smoke" \
  --overwrite_output_dir \
  --per_device_train_batch_size 1 \
  --gradient_accumulation_steps 16 \
  --lr_scheduler_type cosine \
  --logging_steps 1 \
  --save_steps 20 \
  --save_total_limit 1 \
  --learning_rate 1e-5 \
  --timeseries_sft_lr 1e-5 \
  --warmup_ratio 0.02 \
  --num_train_epochs 0 \
  --max_steps 20 \
  --plot_loss \
  --bf16 \
  --save_only_model \
  --save_safetensors false \
  --report_to none \
  --preprocessing_num_workers 8 \
  --trust_remote_code true \
  --cutoff_len 8192
```

如果这档通过，再上探：

```text
per_device_train_batch_size=2, gradient_accumulation_steps=16, cutoff_len=8192
```

如果仍稳定，再上探：

```text
per_device_train_batch_size=1 或 2, cutoff_len=10000
```

通过标准：

- 完成至少 20 个 optimizer update step。
- 日志中出现正常 loss。
- 没有 `CUDA out of memory`。
- 没有 `SIGKILL/-9`。
- checkpoint 能保存。
- 系统盘 `/` 没有明显增长。

### 5.3 Stage 1 正式训练

Stage 1 正式训练建议先按官方步数：

```text
max_steps=1000
```

推荐默认参数：

```text
per_device_train_batch_size=1 或 2，以 smoke 上探结果为准
gradient_accumulation_steps=16 或 32
cutoff_len=8192，稳定后再改 10000
save_steps=250
save_total_limit=1
```

说明：

- 如果 batch=2 能稳定，优先 batch=2。
- 如果 batch=2 OOM，但 batch=1 稳定，不视为失败，继续 full SFT。
- 不建议一开始保存多个 checkpoint；Stage 1 一个模型 checkpoint 已经约 8G 级别，保存优化器状态会更大。

输出目录建议：

```text
output/a800_qwen3_4b_stage1_full
```

## 6. Stage 2：全参 CoT SFT

Stage 2 仍走 full fine-tuning，不切 LoRA。

输入模型：

```text
output/a800_qwen3_4b_stage1_full
```

数据：

```text
entity_cot,etiological_cot,correlation_cot,forecasting_cot
```

推荐参数：

```text
deepspeed=ds_config/zero3.json
finetuning_type=full
bf16=true
flash_attn=fa2
max_steps=400
cutoff_len=8192，Stage 1 的 10000 稳定后再同步到 10000
per_device_train_batch_size 复用 Stage 1 稳定值
gradient_accumulation_steps 复用 Stage 1 稳定值
save_steps=100 或 200
save_total_limit=1
```

输出目录建议：

```text

```

Stage 2 通过标准：

- 完成 400 step。
- loss 正常下降或至少没有异常震荡到 NaN。
- 最终模型目录可被 `AutoModelForCausalLM.from_pretrained(..., trust_remote_code=True)` 加载。
- Stage 3 smoke 能读取该目录。

## 7. Stage 3：单卡 S-GRPO

Stage 3 是最容易显存爆的阶段，因为同时涉及：

- actor。
- reference / logprob。
- rollout engine。
- reward 计算。
- PPO/GRPO update。

这里不建议直接照搬官方 8 卡参数：

```text
data.rollout_batch_size=128
data.val_batch_size=128
worker.rollout.n=8
trainer.n_gpus_per_node=8
```

服务器 2 单卡 A800 80G 的首轮 Stage 3 应该仍然是 full RL，但降低 rollout 并控制 vLLM 显存占用。

推荐 smoke 参数：

```bash
cd /root/autodl-tmp/STReasoner_reproduce

MODEL_PATH=./output/a800_qwen3_4b_stage1+2_full

/root/autodl-tmp/conda/envs/str-py310/bin/python -m src.EasyR1.verl.trainer.main \
  config=./src/EasyR1/examples/config.yaml \
  data.train_files=./data/ST-Bench/ST-RL/etiological_rl.jsonl,./data/ST-Bench/ST-RL/forecasting_rl.jsonl,./data/ST-Bench/ST-RL/correlation_rl.jsonl,./data/ST-Bench/ST-RL/entity_rl.jsonl \
  data.val_files=./data/ST-Bench/ST-Test/etiological_test.jsonl,./data/ST-Bench/ST-Test/forecasting_test.jsonl,./data/ST-Bench/ST-Test/correlation_test.jsonl,./data/ST-Bench/ST-Test/entity_test.jsonl \
  data.prompt_key=input \
  data.ts_key=timeseries \
  data.answer_key=output \
  data.format_prompt=./src/EasyR1/examples/format_prompt/str.jinja \
  data.max_prompt_length=4096 \
  data.max_response_length=1024 \
  data.rollout_batch_size=16 \
  data.val_batch_size=16 \
  worker.actor.model.model_path=${MODEL_PATH} \
  worker.actor.model.trust_remote_code=true \
  worker.actor.model.enable_gradient_checkpointing=true \
  worker.actor.optim.lr=1.0e-7 \
  worker.actor.optim.strategy=adamw_bf16 \
  worker.reward.reward_function=./src/EasyR1/examples/reward_function/str.py:compute_score \
  worker.rollout.n=4 \
  worker.rollout.tensor_parallel_size=1 \
  worker.rollout.gpu_memory_utilization=0.50 \
  trainer.experiment_name=a800_qwen3_4b_stage3_full_smoke \
  trainer.n_gpus_per_node=1 \
  trainer.find_last_checkpoint=false \
  trainer.total_epochs=1 \
  trainer.max_steps=10 \
  trainer.save_freq=10 \
  trainer.save_limit=1 \
  algorithm.enable_spatial_reward=true \
  algorithm.spatial_reward_weight=0.1 \
  data.enable_spatial_reward=true
```

如果 smoke 稳定，再提高：

```text
data.rollout_batch_size: 16 -> 32
worker.rollout.n: 4 -> 6 或 8
worker.rollout.gpu_memory_utilization: 0.50 -> 0.60
trainer.max_steps: 10 -> 按完整 epoch 或固定步数推进
```

Stage 3 的 fallback 顺序：

```text
1. 降 rollout_batch_size。
2. 降 rollout.n。
3. 降 max_prompt_length / max_response_length。
4. 降 vLLM gpu_memory_utilization。
5. 关闭或推迟 val_before_train。
6. 最后再考虑 offload 或参数高效训练。
```

## 9. 失败时怎么判断

### 9.1 Stage 1 / 2 失败

如果报：

```text
CUDA out of memory
```

处理顺序：

```text
1. batch=2 改 batch=1。
2. cutoff_len=10000 改 8192。
3. cutoff_len=8192 改 6144。
4. 保持 full，改用 ds_config/ds_config_3_offload_all.json。
5. 仍失败再考虑 LoRA。
```

如果报：

```text
SIGKILL / return code -9
```

优先查：

```bash
free -h
cat /sys/fs/cgroup/memory.max 2>/dev/null || true
dmesg | tail -n 50 2>/dev/null || true
```

如果是 CPU cgroup 被打满，先降 `preprocessing_num_workers`，再考虑 offload 策略。不要在没有确认原因时直接判定 80G 显存不够。

### 9.2 Stage 3 失败

如果 Stage 3 OOM，不要立即否定 full SFT 的结果。Stage 3 的显存结构和 SFT 不一样，通常是 rollout / vLLM / ref model 抢显存。

处理顺序：

```text
1. worker.rollout.gpu_memory_utilization=0.50 改 0.40。
2. data.rollout_batch_size=16 改 8。
3. worker.rollout.n=4 改 2。
4. data.max_response_length=1024 改 512。
5. trainer.val_before_train=false 或降低 val_batch_size。
```

只有这些都不通，再考虑更结构性的改法。

## 10. 本轮执行顺序

建议按下面顺序推进：

```text
1. Stage 0 门禁检查。
2. Stage 1 full smoke：batch=1, cutoff=8192, 20 steps。
3. Stage 1 full 上探：batch=2, cutoff=8192, 20 steps。
4. Stage 1 full 上探：cutoff=10000, 20 steps。
5. 选择最激进且稳定的参数，跑 Stage 1 1000 steps。
6. Stage 2 full smoke。
7. Stage 2 full 400 steps。
8. Stage 3 full smoke：rollout_batch=16, n=4, max_steps=10。
9. Stage 3 按显存余量提高 rollout 或步数。
```

当前推荐的第一条真实训练主线是：

```text
Qwen3-4B-Instruct-2507
full SFT Stage 1
full SFT Stage 2
full S-GRPO Stage 3
A800 80G GPU-only 优先
LoRA 仅作为后备方案
```
