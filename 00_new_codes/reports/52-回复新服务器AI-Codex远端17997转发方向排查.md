| 配置 | 监听 17997 的位置 | A800 远端 `curl --proxy 127.0.0.1:17997` 是否可用 |
| --- | --- | --- |
| `LocalForward 17997 127.0.0.1:7897` | Windows 本机 | 不够。远端不会因此监听 17997。 |
| `RemoteForward 17997 127.0.0.1:7897` | 远端服务器 | 正确方向。远端会监听 17997，再转回 Windows 本地 7897。 |


## 1. 1 服务器硬证据

### 1.1 远端 curl 通过 17997 成功


我还清空了环境代理变量，只保留命令行 `--proxy http://127.0.0.1:17997`，仍然能得到 `Connection established`。所以这不是被环境变量里的其他代理“误导”。

### 1.2 远端 TCP 直连 17997 成功

在 1 服务器远端用 Python socket 测试：

```python

s.settimeout(3)
```

结果：

```text

```

这说明 1 服务器远端确实能连上自己的 `127.0.0.1:17997`。

### 1.3 `/proc/net/tcp` 能看到 17997 LISTEN

`17997` 的十六进制端口是 `464D`。

在 1 服务器执行：

```bash
awk 'NR==1 || tolower($2) ~ /:464d/ || tolower($3) ~ /:464d/' /proc/net/tcp /proc/net/tcp6 2>/dev/null
```

能看到：

```text
0100007F:464D 00000000:0000 0A ...
```

解释：

- `0100007F` = `127.0.0.1`
- `464D` = `17997`
- `0A` = TCP `LISTEN`

所以 1 服务器远端确实有 `127.0.0.1:17997` 监听。

### 1.4 监听 17997 的进程属于 sshd

进一步按 inode 反查：

```bash
for fd in /proc/[0-9]*/fd/*; do
  target=$(readlink "$fd" 2>/dev/null || true)
  case "$target" in
    socket:\[641571888\])
      echo "$fd -> $target"
      pid=${fd#/proc/}
      pid=${pid%%/*}
      ps -p "$pid" -o pid,ppid,etime,cmd
      break
      ;;
  esac
done
```

结果：

```text
/proc/2457/fd/3 -> socket:[641571888]
PID   PPID   ELAPSED   CMD
2457  824    01:05:03  sshd: root
```

这说明 1 服务器远端 17997 的监听由 `sshd: root` 持有。这个现象非常符合 SSH `RemoteForward` 的工作方式：远端 sshd 打开监听端口，把连接转回本地 Windows 代理。

## 5. 给 A800 的推荐 SSH config

请在 Windows 本地 SSH config 里确认 `RemoteForward` 写在正在连接的 Host 块里，也就是 `autodl-A800`，不是只写在 `autodl-1` 或别的 Host 里。

推荐块：

```sshconfig
Host autodl-A800
  HostName <A800_HOST>
  Port <A800_SSH_PORT>
  User root
  IdentityFile ~/.ssh/id_ed25519
  IdentitiesOnly yes
  ServerAliveInterval 20
  ServerAliveCountMax 6
  TCPKeepAlive yes
  ConnectTimeout 15
  ConnectionAttempts 3
  IPQoS none
  RemoteForward 17997 127.0.0.1:7897
  ExitOnForwardFailure yes
```

说明：

- `RemoteForward 17997 127.0.0.1:7897`：让 A800 远端监听 `127.0.0.1:17997`，流量转回 Windows 本地 `127.0.0.1:7897`。
- `ExitOnForwardFailure yes`：如果远端端口没建起来，SSH 直接失败，避免 VS Code 表面连上但 Codex 登录必失败。
- 如果 Windows 本地代理不是 `7897`，把 `7897` 改成真实本地代理端口。

## 10. 对报告 49 的补充修正
