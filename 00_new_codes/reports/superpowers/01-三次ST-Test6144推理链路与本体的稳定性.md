# 三次 ST-Test 6144 推理：链路、波动与 thinking 复述

## 0. 结论先行

本报告从 **源码 + run1/run2/run3 的 exp** 出发独立分析（探索 memo 见 [`00-探索memo.md`](00-探索memo.md)），主要发现：

1. **链路是确定的，输出是随机的**：三次 run 共用同一 STReasoner-8B、同一 ST-Test 输入与 `temperature=0.2`；timeseries 只经 patch+MLP 嵌入，prompt 无 raw 明文。但 **choice 任务约 13–30% 样本** 的 final `<answer>` 对错在三 run 间翻转；forecasting 数值预测也有约 **59%** 样本 MAE 差 >1。
2. **官方 metrics 只看 `<answer>`**：`evaluate_qa.load_prediction_files` 从 full response 中 **只抽取 answer 段** 计分；`<think>` 再长也不进入 accuracy/MAE。
3. **Thinking 内「数值复述对不上 raw」与 task 对错的关系因任务而异**：run1 上 correlation 的 mismatch 样本 **更常答对**（89% vs 81%）；forecasting 的 mismatch 样本 **几乎全错**（0/141 序列匹配意义下正确）。不能统一说「复述错 ⇒ 答错」或反过来。
4. **复述 mismatch 标签在 run 间部分漂移**：forecasting 约 74%、correlation 约 55% 的 run1 mismatch 样本在三次 run 均为 mismatch；其余为单次/双次 run 独有——与 final answer 翻转并存，说明 **thinking 层与 answer 层都在变**。
5. **Response 长度三 run 几乎相同**（thinking median ~2.1k 字符），run 间指标波动 **不是**「有时写短有时写长」导致。

## 3. 推理与评估链路（Part A）

### 3.1 数据如何进模型

```text
ST-Test jsonl
  ├─ input  ──► prompt 文本（含 Graph、问题、<ts><ts/> 占位）
  └─ timeseries ──► float 数组 ──► TimeSeriesEmbedding（patch=8, MLP×5）──► LLM 多模态 token
```

- 源码：`inference_tsmllm_vllm.py` 的 `prepare_batches()`；嵌入：`inference/vllm/chatts_vllm.py` 的 `TimeSeriesEmbedding`。
- **Patch 间无 cross-attention**；跨 node/跨 patch 推理依赖 LLM self-attention（与 `inspect_mlp_encoder.py` 描述一致）。

### 3.2 生成与评估

| 环节 | 行为 | 对三 run 的含义 |
| --- | --- | --- |
| 采样 | CLI `temperature=0.2`, `max_tokens=6144` | 非 greedy；三次 run 独立采样 |
| 输出格式 | `prompt.json` 要求 thinking + answer | 四任务统一两段式 |
| 评估 | `_extract_tag_content(response)` → 只评 answer | thinking 复述 **不计分** |

### 3.3 三 run 可比性

- 模型：`base_model/STReasoner-8B`（`run.log`）。
- 数据：`data/ST-Bench/ST-Test/*_test.jsonl`。
- 差异：**仅** 各 run 的 vLLM 采样随机种子/轨迹；exp 目录后缀 `_run2_official` / `_run3_official`。

## 5. Thinking 复述与 task 对错（Part C）

### 5.1 Strict mismatch 标签的 run 间稳定性

口径：`<think>` 中 `Node k [a-b]:` 数值列表 vs raw `timeseries`，0/1-based 取优，`max_abs_diff>0.01`（沿用已有 artifact 统计）。

| task | run1 | run2 | run3 | 三 run 交集 | 占 run1 |
| --- | ---: | ---: | ---: | ---: | ---: |
| forecasting | 141 | 141 | 137 | **104** | 74% |
| correlation | 347 | 326 | 348 | **190** | 55% |
| entity | 0 | 1 | 0 | 0 | — |

约 **26–45%** run1 mismatch 样本不在三 run 交集内 → **标签会 drift**（RQ3）。

### 5.2 Mismatch × task 对错（run1，RQ2）

| task | mismatch 组正确率 | 非 mismatch 组正确率 |
| --- | ---: | ---: |
| **correlation** | 309/347 = **89.0%** | 1015/1245 = **81.5%** |
| **forecasting** | 0/141 = **0%** | 1/139 = **0.7%** |

三 run 趋势类似（见 [`artifacts/mismatch_vs_correct.json`](artifacts/mismatch_vs_correct.json)）：correlation 上 mismatch 组仍偏 **更对**；forecasting 上 mismatch 组 **几乎全错**。

**机制解释（RQ4，非训练因果）**：

- Evaluate **不读 thinking** → 复述错本身 **不能** 直接改 metrics。
- Correlation：模型常 **边复述边推理**，mismatch 样本更可能「写得多、推得细」，与 39 中「选择偏差」方向一致（本报告独立复算）。
- Forecasting：mismatch 样本往往 **预测序列本身偏离 gold**；复述窗口错与预测错 **同现**，故看起来「强相关」——仍是关联而非「复述导致 MAE」。

### 5.3 案例（RQ3，读 raw response）

| 类型 | idx | 现象 |
| --- | ---: | --- |
| **Persistent hard** | forecasting 19 | 三 run 均在 Node1 [27-32] strict mismatch；max≈1143；final 预测仍随 run 变 |
| **Window drift** | forecasting 179 | run1/2 写 [62-67]；run3 改写 [61-66] 仍 mismatch |
| **Intermittent** | correlation 503 | run1/2 mismatch；run3 未进 mismatch 集（strict 列表未出现或对齐通过） |
| **Singleton** | entity 1175 | 仅 run2：strict 口径下 4 个窗口 mismatch |

说明 drift 既来自 **「写不写某窗口」**，也来自 **「写出的数字变不变」**。

## 6. 综合讨论

### 6.1 能否用「三次 run」评价模型？

- **Task metrics**：可报告 **均值与波动带**（本仓库 run3 correlation 比 run1 低 ~1pt）。
- **Thinking 复述**：需区分 **persistent core（~55–74%）** 与 **drift 边缘**；单次 run 的 mismatch 列表 **不能** 当作稳定全集。
- **因果**：现有链路 **不支持** 从「thinking 复述错」直接推断「MLP 导致答错」；最多说与 **embedding-only 输入** 下「显式读数不可靠」相容。

### 6.2 与旧 reports 的关系

- 42 的全局 acc/MAE 方向：**印证**。
- 39 的「correlation mismatch 组更对」：**在本报告独立交叉表中再现**；forecasting **方向不同** 是本报告新emphasis。
- 43 的三 run mismatch 计数：**印证** artifact 层；本报告补充 **answer 翻转率 + 任务异质性**。

## 9. 补分析（报告完成后追加）

以下由 [`_analysis/compute.py`](_analysis/compute.py) 扩展产出（2026-05-30），对 §4–§5 做定量延伸。

### 9.1 「翻转」到底长什么样？——RRR / RRW 模式

对 choice 任务，把三 run 的对错记为 R/W，得到 8 种模式（[`artifacts/flip_patterns.json`](artifacts/flip_patterns.json)）：

| task | 三 run 全同（RRR+WWW） | 至少一次翻转 | 最常见翻转模式 |
| --- | ---: | ---: | --- |
| correlation | 1331（83.6%） | **261**（16.4%） | RRW 58、RWR 50、WRR 44（大致对称） |
| entity | 837（70.1%） | **357**（29.9%） | RRW 77、RWR 75、WRR 66 |
| etiological | 180（87.0%） | 27（13.0%） | 各模式 ≤9 |

**解读**：翻转不是「run3 系统性更差」——`RRW`（前对后对）与 `WRR`（前错后对）数量接近。run3 correlation 下降来自 **净 −15 题**（见 §9.2），是随机游走的净效应，不是单向偏置。

### 9.2 全局 acc Δ 能否由逐样本转移解释？

[`artifacts/pairwise_acc_transitions.json`](artifacts/pairwise_acc_transitions.json) 用 run1→run3 的 RR/RW/WR/WW 四格表：

| task | RW（对→错） | WR（错→对） | 净变化题数 | 净变化 / N | 实测 acc Δ |
| --- | ---: | ---: | ---: | ---: | ---: |
| correlation | 93 | 78 | **−15** | **−0.942%** | **−0.942%** |
| entity | 129 | 109 | −20 | −1.675% | −1.675% |
| etiological | 11 | 5 | −6 | −2.899% | −2.899% |

**结论（RQ1 深化）**：run1→run3 的 accuracy 变化 **100% 可由逐样本 RW/WR 账本解释**——没有「神秘第三因素」；但就是 **T=0.2 下 261/357 道 volatile 题的随机净亏损**。

### 9.3 Final answer 翻转 vs thinking mismatch：**大多无关**

[`artifacts/flip_mismatch_cross.json`](artifacts/flip_mismatch_cross.json)（correlation，261 道 flip 样本）：

| 子集 | 题数 | 占 flip 样本 |
| --- | ---: | ---: |
| 三 run 均为 strict mismatch | 25 | 9.6% |
| 至少一个 run 为 mismatch（含上项） | 78 | 29.9% |
| **三个 run 均非 mismatch** | **183** | **70.1%** |

**解读**：**约 7 成** answer 翻转样本在 strict 复述口径下 **从未** 被标为 mismatch。Thinking 复述 drift 与 final 选项波动 **是两条 largely 独立的随机通道**——不能用一个解释覆盖两者。

Persistent mismatch 与 drift 子集的 flip 率（[`artifacts/mismatch_drift_vs_flip.json`](artifacts/mismatch_drift_vs_flip.json)）：correlation 三 run 交集 190 题中 25 题 flip（13.2%）；run1 独有 drift 157 题中 29 题 flip（18.5%）——drift 略高但同量级，**不足以**说「复述标签不稳 ⇒ 答案必翻」。

### 9.4 Forecasting：parser 缺失 vs mismatch

[`artifacts/forecasting_gaps.json`](artifacts/forecasting_gaps.json)：run2 缺 idx 84/262，run3 缺 idx 82；**均不在** 任 run 的 strict mismatch 集。

说明 parser-missing 与「thinking 内数值对不上 raw」是 **不同失败模式**（格式/抽取 vs 复述规则）。
