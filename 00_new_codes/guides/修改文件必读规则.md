## 必须遵守的规则

- 报告语言为中文
- **写代码须加注释**：新增或修改代码时，对非自明的逻辑、分支意图、关键超参/边界条件写简短中文或英文注释；函数/模块顶部可写一两句说明用途；不要堆废话，但也不要留「读不懂为什么这样写」的裸代码
- 不要改我的提示词文件，要写内容自己在后面加文件
- 主实验只评测模型原始 response：response 生成后不得改写、补格式、抽取答案、筛选样本或重跑挑最好结果
- **运行日志**：本仓库内超过 **30 天** 的 `*.log` 全部删除；**不删** `*.md`（含 `reports/` 报告）。详见 [`运行日志清理.md`](运行日志清理.md)。

## 模型缓存与加载经验

- STReasoner-8B 完整权重在 `/root/autodl-tmp/STReasoner_reproduce/base_model/STReasoner-8B/`。
- HuggingFace cache 使用 `/root/autodl-tmp/cache/huggingface`；本地模型已用 symlink 接入该 cache。
- 同一 AutoDL 数据盘正常关机/开机后通常不用重下模型，直接加载即可；释放实例、换机器、清盘才需要重下。
- 跑 smoke 或正式实验可加 `HF_HUB_OFFLINE=1`，用于确认脚本命中本地模型，不重新联网拉权重。
- Stage 2.2 当前脚本硬编码模型名 `Time-HD-Anonymous/STReasoner-8B`，不要误改成未确认的本地别名。

## Stage 2.2 paper_cases 经验

- `run-all` 不应每条样例重新加载一次 8B 模型；优先一次加载、循环复用。
- 先区分“生成失败”和“评测提取失败”；无 `<answer>` 时优先查是否漏加 `prompt.json` 后缀，而不是放宽 evaluate。
- forecasting parser 优先读 `<answer>` 内 JSON/短数组，不要抽全文所有数字。
- 修 parser 时只能写通用规则，不按 sample_id 或 gold 写特例。
- Stage 2.2 默认必须 `--format-prompt true`（与 `inference/prompt.json` 一致）；只有对比旧行为时才关。
- evaluate 以 `<answer>` tag-first 为准；不要用 `Answer:` / 全文抽数字兜底替代生成侧格式修复。
- paper_cases / SmartTest 小样例不能当作论文整体效果；验证论文真实效果要另跑完整 ST-Test 四类任务。

## ST-Test 经验

- ST-Test 四类数据在 `data/ST-Bench/ST-Test/`；完整验证不要用 SmartTest 或 paper_cases 替代。
- 优先使用仓库原始 `inference/inference_tsmllm_vllm.py` 和 `evaluation/evaluate.py`。
- 从文件路径直接跑 `evaluation/evaluate.py` 时加 `PYTHONPATH=.`，否则可能 import 不到 `evaluation` 包。
- 完整跑 ST-Test 时不要每条样例重新加载 vLLM/8B 模型，按任务长进程连续生成。
- ST-Test 正式实验必须用 `max_tokens=6144`；低于 6144 的结果只能记为预跑/链路检查，不能当正式结果。
- `inference/llm_utils.py` 里 worker 要确认真的使用调用方传入的 `SamplingParams`，否则 CLI 的 `--max_tokens` 可能只是摆设。
- 本轮完整 ST-Test `max_tokens=6144` 正式输出在 `exp/sttest_full_*_6144/`（`generated_answer.json` + `evaluation_metrics.json`）；gold 在 `data/ST-Bench/ST-Test/`。逐条对照现场 join，**不要**再导出全量拼接 jsonl 到 `reports/artifacts/` 根目录。

## 术语经验

- `Qwen3TSForCausalLM` 是 STReasoner-8B 的加载架构类名，不代表换成了别的实验模型。
- tokenizer 的 `.decode()` 只是 token id 转字符串的 API，不要把它写成独立实验阶段或正式指标。

## Stage 2.3 paper_cases 经验

- `00_new_codes` 下脚本移动后要先确认仓库根目录识别，避免把 `/root/autodl-tmp` 误当 repo root。
- paper_cases 正式 run-all 前保留首条守门；若 `actual_new_tokens=1` 且 `response` 为空，先停下诊断生成侧。
- summary 里的数据路径必须记录实际 `--dataset`，不要沿用旧默认路径。
- HF `model.generate()` 加 `prompt.json` 后缀若首 token 变成 `<|im_end|>`，不要据此否定模型格式能力；优先用官方 vLLM 链路复核。
- paper_cases 混合任务走官方 vLLM 时，可按 `category` 拆成单任务 JSONL，再分别调用 `inference_tsmllm_vllm.py` 和 `evaluate.py`。
## Stage 2.4 graph ablation 经验

- graph ablation 优先薄封装官方 `inference/inference_tsmllm_vllm.py` 和 `evaluation/evaluate.py`，不要在辅助脚本里重写评分逻辑。
- w/o graph 使用 EasyR1 同款 `Graph Structure:.*?(?=please analyze)`，只改 `input`，不改 timeseries/raw/gold。
- STReasoner-8B 官方 vLLM `worker_vllm_ts` 默认 `gpu_memory_utilization=0.95`，单卡 A100-40GB 可观察到约 39GB 占用；full ST-Test 不要并行开多个同模型 vLLM 进程。
- full ST-Test graph ablation 分批跑：先 w/ graph 四任务，再 w/o graph 四任务；每任务一个官方 vLLM 长进程，最后统一 compare。

## 单卡小模型训练经验

归档结论见 [`t3-autodl2…/16`](../reports/t3-autodl2-三阶段训练复现/16-服务器1旧策略-单卡A100stage1情况报告.md)、[`t3-autodl2…/17`](../reports/t3-autodl2-三阶段训练复现/17-服务器1旧策略-Stage%201%20LoRA%20分段训练经验（500→2000）.md)（LoRA 已终止）、[`t3-autodl2…/15`](../reports/t3-autodl2-三阶段训练复现/15-服务器1旧策略-单卡A100训练复现情况.md)（full FT 不可行）、[`t3-autodl2…/25`](../reports/t3-autodl2-三阶段训练复现/25-服务器2新策略-单卡A800-80G-4B全参训练方案.md)（后续全参主路线）。

- STReasoner checkpoint 对比实验已取消；不要继续 stage2.5 checkpoint paper_cases / ST-Test 对比。
- 单张 A100-40GB 不要承诺完整复现 8 卡论文训练；**不要**在服务器1续训 Stage 1 LoRA（2000 step 断点已归档）。
- 4B 是第一选择，因为仓库已有 `scripts/qwen3-4b-instruct/` 和 `base_model/Config-Qwen3-4B-Instruct-2507/`；1.7B/0.6B 需先适配 TS config。
- 训练前先补齐 ST-Align、ST-CoT、ST-RL 数据；缺训练数据时不要直接开训。
- Stage 3 单卡 S-GRPO 只作为链路验证，不把短跑结果写成论文效果复现。
- checkpoint / 模型实验后必须查系统盘；系统盘爆满常见根因是 `/root/model_archive/STReasoner-8B*` 副本。
- 大模型下载、缓存、归档只放 `/root/autodl-tmp`，不要放 `/root/model_archive` 或 `/root/.cache`。
- `initial_model.py` 保存须 **fp16**；否则 4B 目录可膨胀到约 17G。
- 开训前查磁盘与 cgroup：`df -h / /root/autodl-tmp`、`cat /sys/fs/cgroup/memory.max`（full FT -9 多为 **CPU vmem 顶满**，不是 GPU OOM）。
- conda 脚本须把 env `bin` 进 `PATH`（如 `/root/autodl-tmp/conda/envs/str-py310/bin`），否则 DeepSpeed 编译 CPUAdam 找不到 ninja。
- `bitsandbytes==0.43.1` 在当前 triton 下会 `triton.ops` 报错；AutoDL 实测升到 **0.45.2**。
- 当前 Qwen3-4B TS config 的 `model_type` 是 `qwen3`；time-series 训练钩子要识别 `qwen3`，否则 `timeseries_sft_lr` 和 TS LoRA target 可能不会生效。
- 单卡 4B full fine-tuning + ZeRO-3 CPU offload 会受容器内存上限影响；服务器1 cgroup 约 77GB，optimizer 初始化到约 78GB 会被 `SIGKILL`；`stage1_smoke.sh` 仅作历史排障，**勿重复**。
- LoRA 不要直接用 `lora_target=all`（会误匹配 `Qwen3DecoderLayer`）；显式写 Qwen 线性层，再让 time-series patch 追加 `ts_encoder.mlp.*`。
- Stage 1 LoRA 不要再加 `--additional_target ts_encoder`；与 mlp LoRA 冲突，训练能跑但 `PeftModel.from_pretrained` 标准加载 KeyError；早期 10/100 step 产物因此作废。
- A100 上 Stage 1 LoRA 优先 `bf16 + --flash_attn fa2`；日志须见 FlashAttention-2，不要 SDPA；fp16 可能出现 `grad_norm=nan`、LoRA B 仍零的 **假成功**。
- 本地 smoke 要关闭 W&B：`WANDB_DISABLED=true` 且 `--report_to none`。
- 训练完成后不要只看进程退出码。至少查：`trainer_state.json` 有 step/loss；`adapter_model.bin` 里 **lora_B 全非零**；日志有 `Applied SFT learning rate … to … time-series encoder`；`PeftModel.from_pretrained` 能加载。
- **adapter 接续**（`save_only_model` + `--adapter_name_or_path` 开新 run）只继承权重，**不继承** optimizer / scheduler / global step；不要写成「严格连续训练」。真 resume 须保存 `optimizer.pt`、`scheduler.pt`、`rng_state.pth`、`trainer_state.json` 并用 `resume_from_checkpoint`。
- 训练集小探针（6/30/40 条）只能看形态变化，**不能**当 ST-Test、held-out 或论文 Stage 1 效果；历史 LoRA 2000 step 时 temporal 仍约 6/40。
- 不能说「复现了论文 Stage 1 效果」或「Stage 1 训练充分」；当时路线是 **Qwen3-4B-Instruct LoRA**，不是 STReasoner-8B 官方 8 卡全参。
- **官方训练脚本**：`scripts/qwen3-4b-instruct/train_stage*.sh`（8 卡全参）。**复现侧**（`repro_autodl/experiments/scripts/`）：`env_check.sh`、`prepare_qwen3_4b_ts.sh`、`download_stbench_train_data.sh`、`model_check.py`、`stage2/3_smoke.sh`；`stage1_smoke.sh` 为 full FT 排障。**已删**（2026-06-09）：全部 `stage1_lora_*`、`stage1_adapter_*`。说明见 `experiments/scripts/README.md`。

- 如果只是把已有 full 实验按同一配置多跑几次，输出应放在原实验同层、用相近目录名；优先复用原命令和原评估，不要新建一套分析脚本或 artifact 框架。
