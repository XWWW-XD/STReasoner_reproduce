# 黄浩楠 · 考核汇报总结

> 依据 [[0604保研考核会议-文字稿#黄浩楠]] 整理，供向戚老师复述与组内留档。五位学生同题（STReasoner 复现 + 优化），本篇仅黄浩楠。

---

## 1. 复现范围

| 模块              | 完成情况   | 说明                                                                     |
| --------------- | ------ | ---------------------------------------------------------------------- |
| 评估脚本 `evaluate` | ✅      | 与论文附件指标一致（如预测任务 65.59% 等）                                              |
| SDE 多智能体数据合成管道  | ✅（缩小）  | 流程完整跑通；**仅 3 个节点**拓扑；API 用 **DeepSeek** 替代 OpenAI                      |
| 原模型推理           | ✅      | 云端租卡；下载 **STReasoner-8B** 在 **T1–T4** 上推理 → `answer.json` → 再评估        |
| ST-CoT 数据生成     | ✅（改路径） | 作者未开源数据集；改读取逻辑，用 **8B 的 response** 走生成脚本（非原文 5 次 Claude + 拒绝采样）        |
| 多阶段训练           | ⚠️ (前两阶段)  | 完成 **文本对齐（只训时间序列编码器）** + **ST-CoT 先验注入（LoRA）**；底座 **Qwen3-4B**（非原文 8B） |
| 纯文本消融模型         | ✅      | 与原文一致思路：图/时序当普通文本输入，用于对照时间编码器作用                                        |
| 消融评估            | ✅      | 多模态 vs 纯文本；强调 **coverage** 等指标，解释纯文本在 T4 上 MAE 无穷等                     |
| SGPRO 强化学习      | ❌      | 显存/算力不足，未做                                                             |

**未复现/弱化**：全规模拓扑、OpenAI/Claude 管线、8B 全量微调、RL 阶段。

---

## 2. 复现耗时 · 优化耗时

汇报按 **四周** 自述（与同批约 **5 月初** 起算一致，未给总人日）：

| 阶段 | 时间安排 |
|------|----------|
| 第 1 周 | 读论文 |
| 第 2 周 | 定简短复现计划并开始复现 |
| 第 3 周 | 继续复现；**后半周**开始想优化方案 |
| 第 4 周 | 持续做优化与整理汇报 |

**可量化片段**（口述）：LoRA 相关训练举例 **约 50 分钟 / 1000 step**；SDE/API、云端 8B 推理、ST-CoT 生成等**未报总小时数**。优化四条线并行构思，答辩时 **RAG 展开最多**，其余因时间压缩略讲。

---

## 3. 优化方向（均为本人提出，实践可借助 AI）

1. **RAG**：基于 ST-CoT 建历史时空样本向量库；推理前按时序统计特征检索 Top-K，再按 **图结构 + 摘要 rerank**，**门控阈值** 后弱参考注入 prompt，再调 ST-8B。
2. **答案候选**：每题 **3 条**不同风格推理链，验证集打分选型，低分则自我修正一轮（答辩未展开结果表）。
3. **多智能体联合推理**：仿 SDE 分工，同一 8B 换 prompt 扮演数据分析 / 逻辑推理 / 决策，加规则选择器（**未引入异构模型**，自述为失败因素之一）。
4. **专用图结构编码器**：设想 LM + 时序编码器之外再加图编码器；**未实现**（对齐难、缺 GraphAlign 类数据、显存压力）。

---

## 4. 技术实现（要点）

- **复现**：DeepSeek 小规模 SDE；理清 **answer.json** 字段（题目、节点 TSTS 占位符、think/answer、选项/预测格式）；ST-CoT 字段 `responses` → `response` 的格式对齐。
- **训练**：Qwen3-4B + Chronos 时间编码器；阶段一冻 LM 训编码器；阶段二 **LoRA** 注入 ST-CoT；并行训 **纯文本 Qwen** 做消融。
- **RAG 实现**：时序特征向量（均值、峰谷等）+ metadata（output、summary、图信息）；Top-5 检索 → rerank 打分 → 相似度/差分双阈值门控 → prompt 四条约束（弱参考、禁止照抄历史答案等）+ debug 日志。
- **未做**：RL；图编码器；RAG/候选/多智能体均未在原文训练栈上重新微调。

---

## 5. 优化效果

- **总体（本人结论）**：优化后 **准确率提升不明显，部分任务略降**；汇报态度坦诚，仍展示失败分析与 debug。
- **RAG（有数字）**：举例任务约 **72% vs 原文 ~75%**；门控常因 Top1/Top2 相似度几乎相同而不注入。
- **失败归因（自述）**：  
  - 时序统计特征偏 **全局趋势**，区分度不足；  
  - 向量库来自 **ST-CoT ← ST-Bench 合成数据**，模板/规律相似 → 检索 Top1/Top2 难区分；  
  - 与 **已用 ST-CoT 微调** 的信息重叠，何老师指出「等于又干了一遍训练时的事」，学生认同。
- **答案候选 / 多智能体**：答辩称 **效果不佳或未展开**；图编码器未落地。
- **消融（复现侧，非优化）**：纯文本在 T1–T3 远低于多模态；T4 纯文本 MAE 极差；多模态绝对值也低——归因 **4B、LoRA 非全量、无 RL** 等，但说明 **时序编码器必要** 的结论仍成立。

## 6. 突出能力（组内评价维度）

| 维度 | 表现 |
|------|------|
| **论文查找与理解** | 能概括 ST-Bench / STReasoner / SGPRO 动机、三挑战、主要结果；中期后补充 **answer 格式** 等细节。 |
| **代码与工程** | 改数据路径与字段、跑通 evaluate / SDE / 推理 / ST-CoT 脚本；会用租卡、日志与结果文件对照。 |
| **调优能力** | LoRA + 两阶段对齐；知悉资源约束下选 4B；能设消融对比编码器。 |
| **实验严谨** | 展示原文表 vs 复现表；RAG 留 debug（相似度、是否注入）；覆盖率等辅助指标；主动说「不是作假直接摆数据」。 |
| **数理 / 分析** | RAG 用统计特征与 rerank 加权；能分析合成数据相似性、门控逻辑；对 **信息是否增量** 经提问后反思（ST-CoT vs RAG、真实交通数据设想）。 |

**答辩互动摘要**：认可 RAG 与 ST-CoT 同源时增益有限；认为 **答案候选、未来图编码器** 若增加有效信息链仍有空间；LoRA 用「百科全书贴标签」类比，**机制层面承认未深研**。组内评价侧重 **投入、思考量、表达**，排名约 **65–70%**，**确定留组、无读博打算**，王老师曾评态度与钻研劲较好。

---

## 给戚老师复述时可用的三句话

1. **复现**：评估与 8B 推理对齐论文；管道与训练因算力做了 **3 节点 / 4B / LoRA / 无 RL** 的裁剪，但主线和消融逻辑完整。  
2. **优化**：四条自研方向以 **RAG 实现最深**，实测 **未涨点甚至略降**，原因分析清楚，且接受「与 ST-CoT 训练信息重复」的质疑。  
3. **人**：四周从论文到复现再到优化，**工作量与表达明显强于中期口头汇报**；结果不是最强，但 **过程认真、反思到位**，适合后续跟组补基础。
